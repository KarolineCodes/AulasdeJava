Para cada sorvete dentro do pote...O for-each passeia sozinho.

O for-each é um jeito mais curto de percorrer arrays e listas quando você só quer os valores. Sem início, sem condição, sem passo, sem i. Compare os dois jeitos e veja o apelido pulando de caixinha em caixinha.

String[] sabores

Como ler o for-each

Leia em voz alta: "para cada String chamada sabor dentro de sabores". Os dois pontos : se leem como "dentro de".

StringO tipo do que está dentro da coleção (e não da coleção em si).
saborO apelido: a cada volta, ele vale um item diferente. Você escolhe o nome.
:"dentro de".
saboresO array ou a lista que vai ser percorrida.
// funciona com array... int[] pontos = {3, 7, 2}; for (int p : pontos) { System.out.println(p); } // ...e com ArrayList ArrayList<String> amigas = new ArrayList<>(); amigas.add("Lia"); amigas.add("Mel"); for (String a : amigas) { System.out.println("Oi, " + a + "!"); }

As limitações do for-each

Ele é mais simples, mas é menos flexível. Saiba quando ele não serve:

🔢 Não sabe a posição

Não existe i. Se você precisa mostrar "Nota 1", "Nota 2", use o for com índice.

✏️ Não altera o original

O apelido é uma cópia do valor. Mudar o apelido não muda o array.

for (int p : pontos) { p = p * 2; // o array não muda! }
for (int i = 0; i < pontos.length; i++) { pontos[i] = pontos[i] * 2; }

🗑️ Não remove durante

Remover itens de uma lista dentro do for-each quebra o programa com ConcurrentModificationException.

➡️ Só para frente

Ele anda de um em um, do começo ao fim. Para ir de trás para frente ou pular de dois em dois, use o for normal.

💡 Então, quando usar?

O for-each é o mais recomendado quando você só precisa ler e usar os dados: olhar, comparar, mostrar ou somar os itens, sem mudar a estrutura da lista.

Interface: um contrato 📜

Uma interface é como um contrato ou uma lista de regras. Ela diz o que uma classe precisa saber fazer, mas não como fazer.

Na interface, os métodos ficam sem corpo (sem chaves e sem código), só com um ; no final. Nada roda ali: é só uma promessa. E tudo na interface é public.

Uma classe assina o contrato com a palavra implements. A partir daí, ela é obrigada a escrever o código de todos os métodos que a interface pede, também como public.

Instrumento.java
public interface Instrumento { void tocar(); // sem corpo! }
Violao.java
public class Violao implements Instrumento { @Override public void tocar() { System.out.println("Plim plim 🎸"); } }

Monte sua banda 🎶

Violão, Bateria e Flauta assinaram o contrato Instrumento. Cada uma escreveu o tocar() do seu jeito. Coloque instrumentos na lista e aperte play.

Repare: a lista é do tipo ArrayList<Instrumento> e aceita qualquer classe que assinou o contrato. E o for-each chama tocar() em todos sem nenhum if!

@Override: "confere pra mim?"

O @Override é uma anotação (annotation). Ela não é um código que roda: é um recado para o compilador.

Leia assim: "compilador, este método está aqui para cumprir um contrato. Confere para mim?". Se você errar o nome do método (por exemplo, tocarr()), o Java avisa na hora, em vez de deixar o erro passar escondido.

Ele fica logo em cima de cada método implementado.

Sem @Override, o erro passa quietinho 🤫

public void tocarr() { ... } // o Java acha que é um método novo

Com @Override, o Java avisa 🚨

@Override public void tocarr() { ... } // erro: method does not override // or implement a method from a supertype

Interface como tipo universal

Se várias classes assinam a mesma interface, você pode usar o tipo da interface na variável e guardar qualquer uma delas.

E uma classe pode assinar vários contratos de uma vez, separando por vírgula.

Você já usa isso! List é uma interface, e ArrayList é uma classe que assina esse contrato. Por isso dá para escrever List<String> nomes = new ArrayList<>();.

// uma variável, várias classes Instrumento musica = new Violao(); musica.tocar(); // Plim plim 🎸 musica = new Flauta(); musica.tocar(); // Fiuuu 🪈 // vários contratos public class Piano implements Instrumento, Afinavel { // precisa escrever os métodos das DUAS }

E não dá para fazer new Instrumento(): contrato não vira objeto. Só as classes que assinaram.

Erros que toda iniciante comete (e tudo bem)

Esquecer o public

Na classe, o método do contrato precisa ser public.

void tocar() { ... } // attempting to assign weaker access privileges
public void tocar() { ... }

Não cumprir o contrato todo

Se a interface pede dois métodos, a classe escreve os dois.

// Violao is not abstract and does not // override abstract method tocar()
@Override public void tocar() { ... }

Corpo na interface

Na interface, o método termina com ponto e vírgula.

void tocar() { }
void tocar();

Tipo errado no for-each

O tipo é o do item, não da coleção.

for (String[] s : sabores)
for (String s : sabores)

Desafio: a galeria de formas 🔺

Crie uma interface Forma com dois métodos: double area() e String nome(). Crie as classes Quadrado (com o atributo lado) e Circulo (com o atributo raio) assinando o contrato. Coloque algumas formas num ArrayList<Forma> e, com um for-each, mostre o nome e a área de cada uma com printf e some a área total.

Forma.java
public interface Forma { double area(); String nome(); }
Quadrado.java (o Circulo é parecido, com Math.PI * raio * raio)
public class Quadrado implements Forma { double lado; @Override public double area() { return lado * lado; } @Override public String nome() { return "Quadrado"; } }
Main.java
Quadrado q = new Quadrado(); q.lado = 3; Circulo c = new Circulo(); c.raio = 2; ArrayList<Forma> galeria = new ArrayList<>(); galeria.add(q); galeria.add(c); double total = 0; for (Forma f : galeria) { System.out.printf("%s: %.2f%n", f.nome(), f.area()); total += f.area(); } System.out.printf("Área total: %.2f%n", total);
Quadrado: 9,00 Círculo: 12,57 Área total: 21,57
