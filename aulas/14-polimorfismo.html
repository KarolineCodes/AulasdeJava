Onde o polimorfismo acontece

Polimorfismo é dar a mesma ordem (chamar um método com o mesmo nome) para objetos diferentes, e cada um executar do seu jeito. Ele aparece em três lugares que você já conhece:

mesma classeSobrecarga: vários métodos com o mesmo nome e parâmetros diferentes (aula 09).
extendsSobrescrita: a filha dá @Override num método da mãe (aula 13).
implementsCada classe escreve do seu jeito o método que assinou na interface (aula 12).
As classes do palco
public class Dancarina { void dancar() { System.out.println("Balançando de um lado pro outro 🎶"); } } public class Bailarina extends Dancarina { @Override void dancar() { System.out.println("Pirueta na ponta dos pés 🩰"); } } // a Iniciante não sobrescreve nada: public class Iniciante extends Dancarina { }

Sobrecarga: a lanchonete 🍔

Na mesma classe, três métodos se chamam pedir. O que muda é a quantidade ou o tipo dos parâmetros. O Java olha os argumentos que você mandou e escolhe a versão que combina.

Faça um pedido e veja qual versão acende. E tente o último: nenhuma versão combina!

Lanchonete.java
void pedir(String lanche) { System.out.println("1 " + lanche + ", saindo!"); } void pedir(String lanche, int qtd) { System.out.println(qtd + " " + lanche + ", saindo!"); } void pedir(int combo) { System.out.println("Combo número " + combo + " 🍟"); }
Escolha um pedido.

Estático x dinâmico

Os dois tipos de polimorfismo usam métodos com o mesmo nome. A diferença está nos parâmetros e em quando o Java decide qual versão rodar.

EstáticoDinâmico
Outro nomesobrecarga (overloading)sobrescrita (overriding)
Parâmetrosmudam (quantidade, tipo ou ordem)iguais aos da mãe ou da interface
Ondena mesma classeentre mãe e filha, ou classe e interface
Quando o Java decidena compilação, olhando os argumentosenquanto roda, olhando qual é o objeto de verdade
@Override?não usausa
Exemplopedir(String) e pedir(int)dancar() da Bailarina

💡 Truque para não confundir

Estático = parado, decidido antes de rodar: o compilador já sabe qual versão chamar só de olhar os parâmetros. Dinâmico = em movimento, decidido enquanto roda: a variável pode guardar uma Bailarina ou uma Sambista, e só na hora o Java descobre quem é e chama a versão dela.

Um método que recebe a mãe

Se um método recebe um parâmetro do tipo da mãe (ou da interface), ele aceita qualquer filha. O método não sabe quem vai chegar, e funciona para todas.

É isso que deixa o código flexível: se amanhã nascer uma classe Rapper, o chamarAoPalco já funciona com ela, sem mudar uma linha.

static void chamarAoPalco(Dancarina d) { System.out.print("No palco: "); d.dancar(); } chamarAoPalco(new Bailarina()); chamarAoPalco(new Iniciante());
No palco: Pirueta na ponta dos pés 🩰 No palco: Balançando de um lado pro outro 🎶

A variável manda no que dá pra chamar

Com Dancarina d = new Bailarina();, existem duas coisas:

O tipo da variável (Dancarina) decide quais métodos você pode chamar: só os que a mãe conhece.

O objeto de verdade (Bailarina) decide qual versão roda.

Dancarina d = new Bailarina(); d.dancar(); // ✅ roda a versão da Bailarina d.ficarNaPonta(); // ❌ erro: a Dancarina não conhece

Mesmo que a Bailarina tenha ficarNaPonta(), a variável do tipo Dancarina não deixa chamar.

Uma espiadinha no encapsulamento 👀

Hoje qualquer um pode fazer conta.saldo = -1000;. Com encapsulamento, o atributo fica private e só muda por um método, que pode conferir antes de aceitar.

public class Cofrinho { private double saldo; public void depositar(double valor) { if (valor > 0) { saldo += valor; } } }

Erros que toda iniciante comete (e tudo bem)

Sobrecarga só no retorno

Mudar só o tipo de retorno não vale: os parâmetros precisam mudar.

int pedir(int combo) double pedir(int combo) // erro
void pedir(int combo) void pedir(String lanche)

Sobrescrita sem @Override

Sem a anotação, um erro de parâmetro vira um método novo escondido, e a versão da mãe continua rodando.

void dancar(String ritmo) { }
@Override void dancar() { }

Chamar método que a mãe não conhece

A variável do tipo da mãe só enxerga os métodos da mãe.

Dancarina d = new Bailarina(); d.ficarNaPonta();
Bailarina b = new Bailarina(); b.ficarNaPonta();

Encher o código de if

Se você está testando "se for Bailarina faz isso, se for Sambista faz aquilo", provavelmente o polimorfismo resolve.

if (tipo.equals("bailarina")) {...} else if (tipo.equals("sambista")) {...}
d.dancar(); // cada uma sabe o seu

Desafio: a equipe de heroínas 🦸‍♀️

Crie a classe Heroina com o atributo nome e o método usarPoder(), que mostra "[nome] usou um poder misterioso". Crie Maga e Arqueira, filhas de Heroina, cada uma sobrescrevendo usarPoder() do seu jeito. Na Main, crie um método static void entrarEmCombate(Heroina h) que chama usarPoder() e use ele com as duas. Depois, na Maga, crie duas versões de curar: uma sem parâmetros (cura 10) e uma que recebe a quantidade.

Heroina.java, Maga.java e Arqueira.java
public class Heroina { String nome; void usarPoder() { System.out.println(nome + " usou um poder misterioso"); } } public class Maga extends Heroina { @Override void usarPoder() { System.out.println(nome + " lançou uma bola de fogo 🔥"); } void curar() { curar(10); } // sobrecarga void curar(int pontos) { // sobrecarga System.out.println(nome + " curou " + pontos + " pontos ✨"); } } public class Arqueira extends Heroina { @Override void usarPoder() { System.out.println(nome + " disparou uma flecha certeira 🏹"); } }
Main.java
public static void main(String[] args) { Maga lua = new Maga(); lua.nome = "Lua"; Arqueira sol = new Arqueira(); sol.nome = "Sol"; entrarEmCombate(lua); entrarEmCombate(sol); lua.curar(); lua.curar(25); } static void entrarEmCombate(Heroina h) { h.usarPoder(); }
Lua lançou uma bola de fogo 🔥 Sol disparou uma flecha certeira 🏹 Lua curou 10 pontos ✨ Lua curou 25 pontos ✨
