A filha herda tudo da mãe.E ainda pode ter coisas só dela.

Com extends, uma classe aproveita todos os atributos e métodos de outra, sem copiar uma linha. Clique numa classe da família e veja o que um objeto dela tem: o que é dela, o que veio da mãe e o que veio da avó.

Por que herança?

Imagine um sistema com Aluna, Professora e Coordenadora. Todas têm nome, idade e um jeito de se apresentar(). Sem herança, você escreveria essas mesmas linhas três vezes.

Com herança, você escreve o que é comum uma vez só, numa classe mãe, e as outras herdam. Cada filha só escreve o que tem de diferente.

A regra de ouro é a relação "é um": uma Aluna é uma Pessoa. Uma Influencer é uma Criadora. Se a frase não faz sentido ("um Carro é uma Roda"?), não é caso de herança.

Usuaria.java (a mãe)
public class Usuaria { String nome; int seguidores; void postar() { System.out.println(nome + " postou uma foto 📸"); } }
Criadora.java (a filha)
public class Criadora extends Usuaria { String canal; void fazerLive() { System.out.println(nome + " está ao vivo no " + canal); } }

O fazerLive() usa o nome, que a Criadora nem declarou: ele veio da mãe!

Os nomes da família

Você vai encontrar esses nomes nos erros do compilador e na internet:

Nome técnicoTambém chamada de
superclasseclasse mãe, classe pai, classe base
subclasseclasse filha, classe derivada (a que herda)

O "super" de superclasse não quer dizer "melhor". Quer dizer acima na árvore.

Regras do extends

1 mãe sóUma classe só pode ter uma mãe. Escrever extends A, B dá erro.
só a filha sabeA mãe não sabe que tem filha. Quem declara o extends é só a filha.
herança em cadeiaA neta herda da mãe e da avó. Ela tem tudo que vem de cima.
ObjectToda classe do Java descende da classe Object, a "tataravó" de todas, mesmo sem escrever extends.

Sobrescrita: a filha faz do seu jeito

Sobrescrever é a filha trocar um método que a mãe já tinha por uma versão dela. O método da filha precisa ter o mesmo nome, os mesmos parâmetros e o mesmo retorno.

A mãe continua com o método dela intacto. Quem trocou foi só a filha. E o @Override em cima pede para o compilador conferir se você realmente sobrescreveu algo, igualzinho ao que vimos nas interfaces.

Teste lá em cima: ligue a sobrescrita e chame o postar() numa Influencer e numa Criadora.

Influencer.java
public class Influencer extends Criadora { String marca; @Override void postar() { System.out.println(nome + " postou um publi da " + marca + " ✨"); } }

super: chamando a mãe

A palavra super aponta para a classe mãe. Com super.postar(), a filha consegue usar a versão da mãe e depois acrescentar algo dela, em vez de jogar tudo fora.

É por isso que se chama superclasse: super é "quem está acima".

@Override void postar() { super.postar(); // faz o da mãe primeiro System.out.println("#publi #" + marca); }
Bia postou uma foto 📸 #publi #Lumi

Quem pode ver o quê

A filha herda tudo, mas nem tudo fica visível para ela. Os modificadores de acesso decidem:

Por enquanto, nos exercícios, os atributos ficam sem modificador, e funciona porque as classes estão no mesmo pacote. Mais para frente, no encapsulamento, você vai usar bastante o private.

ModificadorA filha vê?Outras classes veem?

protected na mãe = fechado para fora, aberto para as filhas.

Uma mãe, vários contratos

Uma classe só tem uma mãe (extends), mas pode assinar quantas interfaces quiser (implements). Primeiro vem o extends, depois o implements.

Tente colocar duas mães e o Java responde com um erro na hora.

public class Influencer extends Criadora implements Monetizavel, Verificavel { // tudo da Criadora + métodos dos dois contratos }
public class Influencer extends Criadora, Usuaria // erro: '{' expected

Erros que toda iniciante comete (e tudo bem)

Repetir os atributos da mãe

Se a mãe já tem nome, a filha não declara de novo.

class Criadora extends Usuaria { String nome; // repetido! }
class Criadora extends Usuaria { String canal; // só o que é novo }

Sobrescrita com parâmetro diferente

Mudou os parâmetros? Isso vira um método novo, e o da mãe continua lá. O @Override pega esse erro.

@Override void postar(String legenda) { } // erro: method does not override
@Override void postar() { }

Herança sem "é um"

Herança é para "é um", não para "tem um".

class Celular extends Bateria
class Smartphone extends Celular

Mãe usando coisa da filha

A herança desce, nunca sobe. A mãe não enxerga o que é só da filha.

Usuaria u = new Usuaria(); u.canal = "Lumi"; // erro
Criadora c = new Criadora(); c.canal = "Lumi";

Desafio: o zoológico de bichinhos 🦁

Crie a classe Bicho com os atributos nome e idade e o método comer(), que mostra "[nome] está comendo". Crie Leao e Pinguim, filhos de Bicho. O Leão tem o método rugir(). O Pinguim tem o atributo temperaturaIdeal e sobrescreve o comer() para mostrar "[nome] está comendo peixe gelado a [temperaturaIdeal]°C". Na Main, crie os dois e chame todos os métodos.

Bicho.java
public class Bicho { String nome; int idade; void comer() { System.out.println(nome + " está comendo"); } }
Leao.java e Pinguim.java
public class Leao extends Bicho { void rugir() { System.out.println(nome + ": ROAAAR! 🦁"); } } public class Pinguim extends Bicho { int temperaturaIdeal; @Override void comer() { System.out.println(nome + " está comendo peixe gelado a " + temperaturaIdeal + "°C 🐧"); } }
Main.java
Leao leo = new Leao(); leo.nome = "Leo"; leo.comer(); leo.rugir(); Pinguim pipa = new Pinguim(); pipa.nome = "Pipa"; pipa.temperaturaIdeal = -2; pipa.comer();
Leo está comendo Leo: ROAAAR! 🦁 Pipa está comendo peixe gelado a -2°C 🐧
