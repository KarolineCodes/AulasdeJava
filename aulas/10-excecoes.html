Todo programa pode tropeçar.O try/catch é a rede de segurança.

Quando algo dá errado enquanto o programa roda (como dividir por zero), o Java "lança" uma exceção. Sem tratamento, o programa cai. Com try/catch, ele cai na rede, se recupera e continua. Experimente com b = 0, com e sem a rede!

O que é uma exceção?

É um erro que acontece enquanto o programa está rodando: a pessoa digita letra onde era número, uma conta divide por zero, o código tenta abrir uma caixinha de array que não existe.

Quando isso acontece, o Java cria um objeto que descreve o problema e o "joga para cima". O nome técnico é lançar (throw). Se ninguém pegar esse objeto no caminho, o programa para e mostra aquele texto vermelho no console.

Tratar a exceção é pegar esse objeto antes que ele derrube tudo, decidir o que fazer e seguir em frente.

try, catch e finally

try"Tenta rodar isso aqui." O Java executa linha por linha. Se uma linha der erro, ele abandona o try na hora: as linhas seguintes do try não rodam.
catchO plano B. Só roda se deu erro no try e se o tipo da exceção combinar. O e é o objeto do erro.
finallyOpcional. Roda sempre, com erro ou sem. Serve para "fazer a faxina", como fechar o Scanner.

Depois disso tudo, o programa continua normalmente. Essa é a mágica!

try { int[] pontos = {5, 8, 2}; System.out.println(pontos[7]); System.out.println("Esta linha não roda"); } catch (ArrayIndexOutOfBoundsException e) { System.out.println("Posição inválida! " + e.getMessage()); } finally { System.out.println("Isso sempre roda."); } System.out.println("O programa continua!");
Posição inválida! Index 7 out of bounds for length 3 Isso sempre roda. O programa continua!

O e.getMessage() mostra a mensagem do Java sobre o erro.

Vários catch: a ordem importa

Um try pode ter vários catch, um para cada tipo de problema. O Java testa de cima para baixo e entra no primeiro que combinar.

O catch (Exception e) pega qualquer exceção, então ele precisa ser o último. Se vier antes, os de baixo nunca seriam alcançados e o código nem compila.

try { // código que pode falhar } catch (ArithmeticException e) { System.out.println("Conta impossível!"); } catch (NullPointerException e) { System.out.println("Algo estava vazio!"); } catch (Exception e) { // sempre por último System.out.println("Erro inesperado: " + e.getMessage()); }

Scanner à prova de erros

Lembra do InputMismatchException da aula 05, quando alguém digita texto no nextInt()? Agora dá para tratar! Mas tem uma pegadinha: o texto errado continua na fila do teclado.

Se o seu código estiver dentro de um loop, ele vai tentar ler o mesmo texto errado de novo e de novo, e vira loop infinito. Por isso, dentro do catch, coloque um sc.nextLine() para jogar fora o que foi digitado. É o primo do "Enter fantasma"! 👻

E não esqueça o import: import java.util.InputMismatchException;

int gatos = -1; while (gatos < 0) { System.out.print("Quantos gatos você tem? "); try { gatos = sc.nextInt(); } catch (InputMismatchException e) { System.out.println("Digite um número! 🐱"); sc.nextLine(); // joga fora o texto errado } }

Para saber mais: Error e checked

Error x Exception

Uma Exception é um problema no seu código que dá para tratar. Um Error é a máquina sem recursos, como falta de memória (OutOfMemoryError) ou um método que chama a si mesmo para sempre (StackOverflowError). Na prática, Error não se trata: o programa morre.

Checked x Unchecked

As unchecked (como todas da tabela acima) o compilador não cobra: o código compila e pode quebrar ao rodar. As checked (como IOException, ao mexer com arquivos) o compilador obriga a tratar, senão nem compila.

Erros que toda iniciante comete (e tudo bem)

Catch vazio

O erro acontece e ninguém fica sabendo. Sempre avise algo.

catch (Exception e) { }
catch (Exception e) { System.out.println("Erro: " + e.getMessage()); }

Try gigante

Deixe no try só o que pode falhar. Fica mais fácil saber o que deu errado.

try { /* o programa inteiro */ }
try { n = sc.nextInt(); }

Exception primeiro

O genérico vai por último.

catch (Exception e) {...} catch (ArithmeticException e) {...}
catch (ArithmeticException e) {...} catch (Exception e) {...}

Esquecer de limpar o Scanner

Sem o sc.nextLine() no catch, o texto errado fica na fila e o loop nunca acaba.

catch (InputMismatchException e) { System.out.println("Erro!"); }
catch (InputMismatchException e) { System.out.println("Erro!"); sc.nextLine(); }

Desafio: dividindo as figurinhas 🃏

Peça com o Scanner quantas figurinhas existem e entre quantas amigas elas vão ser divididas. Mostre quantas cada amiga ganha e quantas sobram (lembra do %?). Trate dois problemas: alguém digitar texto em vez de número e alguém digitar 0 amigas. No final, com erro ou sem, mostre "Obrigada por usar o divisor! 💜".

import java.util.InputMismatchException; import java.util.Scanner; public class Figurinhas { public static void main(String[] args) { Scanner sc = new Scanner(System.in); try { System.out.print("Figurinhas: "); int total = sc.nextInt(); System.out.print("Amigas: "); int amigas = sc.nextInt(); System.out.println("Cada uma ganha: " + (total / amigas)); System.out.println("Sobram: " + (total % amigas)); } catch (InputMismatchException e) { System.out.println("Digite só números!"); } catch (ArithmeticException e) { System.out.println("Precisa ter pelo menos 1 amiga!"); } finally { System.out.println("Obrigada por usar o divisor! 💜"); sc.close(); } } }

Quer ir além? Coloque tudo num while para o programa perguntar de novo quando a pessoa errar (e não esqueça do sc.nextLine() no catch!).
